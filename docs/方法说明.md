# 方法说明：统计口径与操作指引

本文件说明 fwtrial 的估计口径、不确定性处理与两类角色的使用方式。
字段含义以 docs/资料口径.md 为准；本文件不重复字段定义。

## 1. 试验口径：计划与实际分开

- **计划口径（ITT）**：按 assignment 的安排版本分组，回答"安排新固件这一
  策略"的效果，包含升级失败与回退的代价。
- **实际口径（as-treated）**：按 resident 的实际驻留版本分组，回答固件
  本身的效果，是主要口径。
- 安排与实际不一致的组日（升级失败、回退后）在两口径间归属不同，报告
  同时给出两者，不得混用。
- **回退后平静时段**（回退后安排仍为新而实际为旧的组日）在实际口径中属
  旧版暴露，在计划口径中是策略成本；任何口径都不得记为新固件收益。
- 严重事件干预/回退所在组日整体剔除出收益类暴露（干预后的平静不能记为
  收益），但该日及其严重事件仍计入安全类指标。

## 2. 事件化：合并、重复与独立

- 同一 event_id 的多条报送是**重复报送**，只算一个事件；
- 同一事件覆盖多个可比语义（family）是**合并告警**，按 family 展开计数；
- 不同 event_id 是**真实独立事件**。
- 所有计数在 family 层进行：代码改名（如 A1→T01 同属 thermal）不算改善。

## 3. 指标（单位有效运行暴露）

暴露 = resident.run_hours（已剔除停机），按口径分组求和。

- **无效打扰率**：经核实不需要处置的告警事件 / 收益暴露小时。
- **漏处置风险**：无告警组日经登记抽查发现需要处置的事件 / 总暴露小时。
- **处置延迟**：经核实需处置事件的处置延迟分布（中位数为主）。
- **严重事件率**：干预/回退次数 / 总暴露小时。

## 4. 核实选择进入安全解释

- 定向核实 π=1；登记抽查 π=登记概率（当前 0.2）。估计用
  Horvitz–Thompson 逆概率加权：一次 π=0.2 的阳性抽查代表 5 起。
- **待核实与未检查不算阴性**：不进入分子分母，而是形成识别界
  [最好情形, 最坏情形]，界宽即不可识别部分。
- 未执行的计划不进入效果分母；同一事件的重复核查只保留最早一次已执行
  结果，不增加样本量。
- 已执行抽查的概率与结果回流后按上述规则加权；抽查概率变化时跨期比较
  须重新加权。

## 5. 站内关联与不确定性

- 同站两组共享班组与功率控制：一组告警减少可能使另一组得到更及时处置。
  组间对比估计的是"存在外溢时的系统级效果"；无干扰的设备级效果**不可
  识别**，报告中明示。
- 不确定性用**站级整群 bootstrap**（以站为单位重抽样），并报告站级
  ICC、设计效应与有效样本量。站数少时区间必然很宽，不得以组日数冒充
  独立样本。
- 负荷与设备年龄随时间变化：报告粗率与负荷标准化率，两者不一致时以
  标准化率为准，并检查均衡性表。

## 6. 查看纪律

- 主要指标与查看日在 review_policy 事先登记；登记查看按 O'Brien–Fleming
  型 α 消耗给出逐次边界，信息量以累计有效暴露小时计。
- 临时查看（未登记的截止）只给描述性结果，区间按已发生查看次数做
  Bonferroni 加宽；反复查看不会让证据越来越确定。
- 中期后改变范围或核实策略会开启新纪元（epoch）：原试用结论与新策略的
  后续观察分开报告，不混池。

## 7. 扩围决策

对每份申请（候选站、允许安全风险增量、希望打扰减少量、设备数）：

1. 安全：漏处置风险差与严重事件率差的上界不得超过允许增量，越限即
   **暂停**；
2. 证据：无告警抽查不足或指标不可估时 **继续试用**；
3. 容量：按新版单位强度外推核实与处置工作量，超过站容量时 **限定规模
   扩围**（给出可支持台数），否则 **支持扩围**；
4. 护栏：容量只限制规模与核实安排，绝不进入安全估计；需处置事件永远
   计入指标，不得因现场忙不过来而排除后再宣称达标。

## 8. 复核与回查

- 每次决定记录观察截止点、代码映射摘要与核实事实摘要。
- 决定截止之后才可知的事故核实，若需处置或仍悬而未决，且落在决定覆盖
  的站，则该决定标记为 **需要复核** 或 **待复核观察项**。
- `trace` 可从任一扩围决定回查：试用安排（计划/实际暴露、不一致天数、
  干预天数）、核实任务实际落实（已执行/待执行/重复剔除）与后续复核。

## 9. 操作指引

- **值班人员**：`python3 -m fwtrial plan --date <日期>` 给出当日该检查谁
  （定向疑点优先，抽查保底）。执行后把结果按 verifications 契约回流，
  随机抽查须带登记概率；补检同一事件不会增加样本量。
- **安全负责人**：`analyze` 看效果与不可识别部分；`decide` 看四档决定
  与理由；`review` 在每次新事实到达后运行；`trace` 回查任一决定。
- 台账（out/ledger.jsonl）是审计依据，只增不改；重新分析不会覆盖历史
  决定。
